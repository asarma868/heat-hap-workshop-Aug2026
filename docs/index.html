Welcome

(About 5 minutes)

A note on the data before we start. Everything in this workshop is simulated. It is built to loosely resemble the scale and population characteristics reported in the PRIME-Boston Boston Emergency Services Team (BEST) papers (roughly 6,500 to 8,200 psychiatric ED encounters per warm season, a population that is predominantly publicly insured or uninsured, individually geocoded and linked to gridded ambient temperature), but the specific counts, effect sizes, and the “true” intervention effect below are all invented for teaching purposes. Nothing here is a re-analysis of real BEST data, and nothing here should be read as an estimate of whether any real intervention worked. The point of the exercise is methodological: we know the ground truth we built into the simulation, so we can watch each design either recover it or fail to.

Learning objectives. By the end of this workshop you will be able to:

  1. Build a synthetic person-day dataset with realistic structure: a daily heat exposure series, drifting population composition, a secular trend, and a known intervention effect.
  2. Implement a time-stratified case-crossover analysis and explain what it does and does not control for.
  3. Implement a difference-in-differences (DiD) analysis through a reusable model_generalized() function, and build a proper event-study plot with year-by-year estimates relative to the intervention.
  4. Build inverse probability weights to address compositional drift in a pre/post comparison, and feed them into the same model_generalized() function used for the DiD estimate.
  5. Compare all three estimates against the known ground truth and discuss which assumptions each design leans on, tying back to the critique of the Ahmedabad HAP evaluation.

A namespace note, since it trips people up constantly. MASS exports its own select() function (for stepwise model selection), completely unrelated to dplyr::select(). Whichever package you library() last wins any naming collision, so if you load MASS after dplyr, every select(...) call in your script silently starts calling MASS::select() instead, and you’ll get a confusing unused arguments error the moment you try to pick columns. Loading dplyr last (as above) fixes it, but the safest habit is to just write dplyr::select() explicitly anywhere it matters, which is what we do below.
